# Список тест-кейсов проекта автоматизации (Test Cases Specification)

В данном документе представлено детальное описание всех автоматизированных сценариев для API- и UI-компонентов проекта EasyRPA.

---

## 🔑 Функциональность: Управление нодами (Node CRUD & File Operations)

### TC-API-001
*   **Название (Title):** Успешное создание новой изолированной ноды
*   **Функциональность (Feature):** Node Management
*   **Тип теста:** API
*   **Приоритет (Priority):** Critical
*   **Тег (Tag):** `@smoke`
*   **Предусловия (Preconditions):**
    1. Пользователь имеет валидные `CLIENT_ID` и `CLIENT_SECRET`.
    2. У пользователя в JWT-токене присутствует право на создание объектов (`"Node": [1]`).
*   **Шаги (Steps):**
    1. Отправить POST-запрос на эндпоинт `/api/v1/node` с валидным JSON-телом, содержащим уникальное имя ноды (например, "Brand New Isolated Node").
    2. Проверить статус-код ответа сервера.
    3. Проверить структуру ответа на наличие сгенерированного ID и соответствие имени.
    4. Выполнить очистку данных: отправить DELETE-запрос для удаления созданной ноды.
*   **Ожидаемый результат (Expected result):**
    *   Сервер возвращает статус-код `200`.
    *   В теле ответа присутствует свойство `id`.
    *   Поле `name` в ответе полностью совпадает с отправленным в запросе.
*   **Статус автоматизации:** Automated ✅

### TC-API-002
*   **Название (Title):** Получение детальной информации о ноде по её идентификатору (ID)
*   **Функциональность (Feature):** Node Management
*   **Тип теста:** API
*   **Приоритет (Priority):** High
*   **Тег (Tag):** `@smoke`
*   **Предусловия (Preconditions):**
    1. В системе предварительно создана нода с известным ID (например, через `beforeEach`).
    2. У пользователя есть права на чтение объектов (`"Node": [0]`).
*   **Шаги (Steps):**
    1. Отправить GET-запрос на эндпоинт `/api/v1/node/{activeNodeId}`.
    2. Проверить статус-код ответа.
    3. Проверить тело ответа на соответствие ID и имени предсозданной ноды.
*   **Ожидаемый результат (Expected result):**
    *   Сервер возвращает статус-код `200`.
    *   Возвращенный объект содержит верный `id`.
    *   Поле `name` содержит точное значение "Pre-created Autotest Node".
*   **Статус автоматизации:** Automated ✅

---

### TC-API-003
*   **Название (Title):** Успешное обновление полей существующей ноды
*   **Функциональность (Feature):** Node Management
*   **Тип теста:** API
*   **Приоритет (Priority):** Medium
*   **Тег (Tag):** `@regression`
*   **Предусловия (Preconditions):**
    1. В системе предварительно создана нода с известным ID.
    2. Пользователь авторизован в системе.
*   **Шаги (Steps):**
    1. Сгенерировать валидный JSON-пайлоад с обновленным именем ноды ("Updated Autotest Node Name").
    2. Отправить PUT/POST-запрос на обновление ноды по её ID.
    3. Проверить статус-код ответа.
    4. Проверить, что имя ноды изменилось в ответе сервера.
*   **Ожидаемый результат (Expected result):**
    *   Сервер возвращает статус-код `200`.
    *   Поле `name` в ответе успешно изменилось на новое значение из пайлоада.
*   **Статус автоматизации:** Automated ✅

### TC-API-004
*   **Название (Title):** Удаление ноды и проверка отсутствия доступа к ней
*   **Функциональность (Feature):** Node Management
*   **Тип теста:** API
*   **Приоритет (Priority):** High
*   **Тег (Tag):** `@regression`
*   **Предусловия (Preconditions):**
    1. В системе предварительно создана нода с известным ID.
    2. Текущая сессия сброшена для шага `afterEach` (`activeNodeId = 0`), чтобы избежать дублирующего удаления.
*   **Шаги (Steps):**
    1. Отправить DELETE-запрос на удаление ноды по её ID.
    2. Проверить статус-код ответа на успешное удаление.
    3. Отправить повторный проверочный GET-запрос на получение данных этой же ноды по сохраненному ID.
    4. Проверить статус-код ответа на чтение удаленного объекта.
*   **Ожидаемый результат (Expected result):**
    *   Первый запрос удаления возвращает статус-код `200`.
    *   Повторный запрос чтения удаленной ноды возвращает статус-код `403` (Доступ запрещен/Объект скрыт) или `404` (Не найдено).
*   **Статус автоматизации:** Automated ✅

### TC-API-005
*   **Название (Title):** Скачивание параметров ноды в формате CSV-файла
*   **Функциональность (Feature):** Node File Operations
*   **Тип теста:** API
*   **Приоритет (Priority):** High
*   **Тег (Tag):** `@regression`
*   **Предусловия (Preconditions):**
    1. В системе существует нода с заполненными параметрами.
*   **Шаги (Steps):**
    1. Отправить GET-запрос на эндпоинт загрузки параметров `/api/v1/node/{id}/params/download`.
    2. Проверить статус-код ответа сервера.
    3. Проверить заголовки ответа (`content-type`) на соответствие бинарному или CSV типу данных.
    4. Извлечь тело ответа в виде буфера данных и проверить, что размер файла больше 0 байт.
    5. Преобразовать буфер в UTF-8 строку и проверить наличие базовой структуры структуры заголовков CSV (поля key и value).
*   **Ожидаемый результат (Expected result):**
    *   Сервер возвращает статус-код `200`.
    *   Заголовок `content-type` содержит `text/csv` или `application/octet-stream`.
    *   Размер скачанного файла (`fileBuffer.length`) больше нуля.
    *   Текст файла содержит валидные заголовки колонок (соответствует регулярному выражению `/key.*value/`).
*   **Статус автоматизации:** Automated ✅
