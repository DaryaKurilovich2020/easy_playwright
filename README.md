# 1. Название проекта
> Автоматизация тестирования RPA-платформы EasyRPA (API & UI)

---

## 2. Описание тестируемого сайта
Проект предназначен для автоматизированного тестирования платформы **EasyRPA** (доступна по адресу: `https://easyrpa.eu`). Платформа представляет собой веб-интерфейс и набор API-эндпоинтов для управления изолированными нодами (Nodes), сценариями автоматизации, пользователями и системными параметрами.

---

## 3. Используемый инструмент
*   **Playwright Test** (TypeScript) — основной фреймворк для сквозного (E2E) и API тестирования.
*   **ESLint** — статический анализ и проверка качества кода.
*   **Prettier** — автоматическое форматирование кода под единый стиль.

---

## 4. Версия Node.js
Для стабильной работы проекта требуется **Node.js LTS** (версия **20.x** или выше).

---

## 5. Инструкция по установке
1. Склонируйте репозиторий с проектом:
   ```bash
   git clone https://github.com/DaryaKurilovich2020/easy_playwright
   cd easy_playwright
   ```
2. Установите все необходимые зависимости (включая линтеры и форматтеры):
   ```bash
   npm install
   ```
3. Установите системные зависимости и браузеры для Playwright:
   ```bash
   npx playwright install --with-deps
   ```

---

## 6. Инструкция по локальному запуску
Перед запуском тестов обязательно создайте файл `.env` в корне проекта на основе примера `.env.example` и заполните его вашими секретными данными (см. раздел 17).

---

## 7. Команды запуска UI-тестов
Запуск всех пользовательских интерфейсных тестов в графическом режиме (UI Mode):
```bash
npx run test:ui
```
Запуск UI тестов в фоновом режиме (Headless):
```bash
npx run test:headed
```

---

## 8. Команды запуска API-тестов
Запуск изолированных тестов для API-контроллеров (из папки `tests/api`):
```bash
npx run test:api
```

---

## 9. Команду запуска smoke-набора
Запуск критически важных тестов (Smoke), помеченных специальным тегом:
```bash
npx run test:smoke
```

---

## 10. Команду запуска regression-набора
Запуск полного набора регрессионных тестов (включает абсолютно все UI- и API-тесты проекта):
```bash
npx run test:regression
```

---

## 11. Команду запуска lint
Запуск статического анализатора ESLint для поиска ошибок и неиспользуемого кода:
```bash
npm run lint
```
Для автоматического исправления мелких ошибок линтера:
```bash
npx eslint . --fix
```

---

## 12. Команду проверки форматирования
Проверка соответствия кода правилам стиля Prettier (без изменения файлов):
```bash
npm run format:check
```
Для автоматического форматирования всех файлов в проекте:
```bash
npm run format
```

---

## 13. Команду открытия report
Для открытия последнего сгенерированного локального HTML-отчета о прохождении тестов:
```bash
npx run report
```

easy_playwright/
├── .github/

│       ├── api-tests.yml   # Запуск изолированных API-тестов

│   └── fixtures/           # Кастомные фикстуры Playwright

## 15. Описание тегов
*   `@smoke` — используется для маркировки критически важных тестов (например, успешная авторизация, CRUD-операции для ноды). Должен выполняться быстро и всегда оставаться "зеленым".
---

## 16. Описание GitHub Actions
В проекте настроены три независимых автоматических процесса (Workflows):
1.  **API Tests** (`api-tests.yml`) — Запускается при push в ветку `master`, при создании PR и вручную. Устанавливает зависимости через `npm ci`, проверяет код линтером/форматтером, прогоняет только API-тесты и прикрепляет архив отчета в артефакты.
2.  **Smoke Tests** (`smoke-tests.yml`) — Запускается при push, PR и вручную. Скачивает репозиторий, разворачивает браузеры и прогоняет тесты с тегом `@smoke`. В случае падения прикрепляет скриншоты, трассировки и видеозаписи ошибок.
3.  **Full Regression Tests** (`regression-tests.yml`) — Запускается вручную или автоматически по расписанию (**раз в сутки в 02:00 UTC**). Проводит полный цикл UI- и API-тестирования.

---

## 17. Информацию о необходимых environment variables
Проект использует переменные окружения, которые локально считываются из `.env`, а в CI берутся из зашифрованных GitHub Secrets.
Необходимые ключи:
*   `CLIENT_ID` — уникальный идентификатор клиента для авторизации в RPA-платформе.
*   `CLIENT_SECRET` — секретный ключ для генерации OAuth2 токена.
*   `GRANT_TYPE` — тип авторизации (например, `client_credentials`).
*   `SCOPE` — уровень доступа приложения (например, `rpaplatform`).

---

## 18. Известные ограничения проекта
*   **Конфликт удаления нод при параллельном запуске**: Тесты используют единую тестовую учетную запись. При одновременном параллельном запуске тестов `CREATE` и `DELETE` в несколько потоков, id ноды в `afterEach` может перезатереться. Рекомендуется запуск в 1 поток (`workers: 1`) для стабильности API.
*   **Зависимость от стабильности тестового стенда**: Веб-сайт `cs2.easyrpa.eu` может периодически обновляться разработчиками, что может приводить к временным падениям UI-тестов из-за изменения структуры страниц (в этом случае для CI настроены `retries: 2`).
